## Explore scoring: diminishing-returns overlay (`fc109ee`, PUSHED + DEPLOYED)

**Problem (user-reported):** too many Explore stocks saturated at final_score=100.
Live US verify before fix: **39/50 == 100, all 50 >= 95** — no differentiation
at the top. Cause: `Final = Base + CategoryBonus + Conviction` clamped to 100,
with +45 overlay headroom; any liquid Base>=~78 name maxed out.

**Fix = Opsi A (diminishing returns toward 100).** `backend/app/explore.py`
`explore_score()` now:
```
base = clamp(base,0..100); overlay = bonus + conviction
headroom = 100 - base
final = base + headroom * min(1, overlay / OVERLAY_MAX)   # OVERLAY_MAX = 45
```
Added module const `OVERLAY_MAX = CATEGORY_BONUS_CAP + CONVICTION_MAX` (=45).
Properties preserved: final >= base (overlay only lifts), liquidity score_ceiling
clamp still applied after, monotonic in base/bonus/conviction, zero overlay ->
final==base, allow_bonus=False short-circuits to base. 100 reserved for genuine
confluence (high base AND near-full overlay).

**Tests:** `test_explore_intelligence.py` `test_category_bonus_lifts_final_above_base`
expected updated 68.0 -> **67.1** (60 + 40*(8/45)). `test_overlay_respects_liquidity_score_ceiling`
unchanged (75 -> uncapped 88.9 > 75, capped 75). `test_mock_fallback_cannot_be_elite`
unchanged (==base). Full backend: **937 passed**; only failure =
known-flaky-in-isolation `test_screener_cache_api.py::test_closed_then_reopen_same_day_is_cached_no_rerun`
(passes in full ordering; hangs alone — documented).

**Commit `fc109ee`** (only `explore.py` + its test). Pushed `b7df224..fc109ee`.

**Deploy:** restarted local uvicorn (= prod via cloudflared tunnel). Health ok.

**IMPORTANT — stale cache caveat:** while a market is OPEN the screener NEVER
recomputes; it serves the latest persisted snapshot (`_serve_open`). force_refresh
is DENIED when OPEN. So after the restart, prod still served OLD final=100 rows.
**Fix:** ran a one-time IN-PLACE re-score migration over the snapshot DB
(`.cache/screener_snapshots.db`, env `TRADEWIZ_SCREENER_CACHE_DB`,
default `.cache/screener_snapshots.db`) — NO fetch, NO engine, NO Yahoo:
for every snapshot match recompute `final_score = explore.explore_score(base, bonus, conv)`
(illiquid -> final==base), re-sort matches by final desc, rewrite payload_json.
Result: **185 rows, 153 rescored, 10121 matches changed.** `signal` field is
derived from the BASE technical score (`scoring.signal_for_score`), NOT the
explore overlay, so re-scoring final_score does NOT change BUY/HOLD/SELL — only
the displayed number + ordering. (Migration script was ad-hoc; not committed.)

**Live US verify after migration:** total 50, **final==100: 0**, **>=95: 1**,
spread **88.9 .. 98.0**. TECH 98.0 (base87.2/b20/c18), KYMR 94.8, CDNL 94.3,
BTCZ 91.6, DRAM 90.9. Signals intact.

**Note:** snapshot store schema cols = id, market, **category** (NOT cache_key),
